## מה נדרשנו לעשות

להקים אתר **Drupal** שמציג את מושגי הקורס, כשכל רכיבי המערכת רצים ב-**Docker**:

1. להקים רשת Docker, קונטיינר של בסיס נתונים וקונטיינר של Drupal.
2. להגדיר את Drupal: שפה, חיבור לבסיס הנתונים, שם האתר, משתמש מנהל ומשתמשים לחברי הצוות.
3. להוסיף לאתר תכנים ממילון המושגים של הקורס.
4. לגבות את בסיס הנתונים ולשחזר אותו על מכונת Linux אחרת.
5. לכתוב סקריפטים שמבצעים אוטומטית הקמה, גיבוי, שחזור וניקוי.
6. לשמור את הסקריפטים ואת קבצי הגיבוי במאגר Git משותף.

## מה עשינו

- **בסיס נתונים:** בחרנו ב-PostgreSQL. הוא רץ בקונטיינר `drupal-db`, חשוף על פורט `5432`, עם משתמש העל `root` והסיסמה `my-secret-pw`.
- **Drupal:** רץ בקונטיינר `drupal-app`, חשוף על פורט `8080`. שני הקונטיינרים מחוברים לרשת `drupal-net`, ו-Drupal מתחבר לבסיס הנתונים לפי שם הקונטיינר (`drupal-db`).
- **הגדרת האתר:** האתר בעברית, בשם "האתר של יובל ולי ים". המשתמש המנהל הוא `demoadmin` עם הסיסמה `secretpass`, ולכל אחד מחברי הצוות יש משתמש משלו (`yuval`, `liam`).
- **תוכן:** הוספנו 9 מושגים ממילון המושגים של הקורס (Git, Linux ו-Bash) ככתבות עם תגיות.
- **נתונים קבועים:** בסיס הנתונים נשמר ב-volume בשם `drupal-db-data`, ותיקיית `sites` של Drupal (שבה `settings.php` והקבצים שהועלו) נשמרת ב-volume בשם `drupal-sites`.
- **גיבוי:** מגבים גם את בסיס הנתונים (`pg_dump`) וגם את תיקיית `sites`. בלי `settings.php`, Drupal שמשוחזר על מכונה חדשה פותח שוב את אשף ההתקנה.

### קבצים במאגר

| קובץ | תפקיד |
|---|---|
| `setup.sh` | יוצר את הרשת, מוריד את ה-images העדכניים ומריץ את קונטיינר בסיס הנתונים ואת קונטיינר Drupal |
| `backup.sh` | מגבה את בסיס הנתונים ל-`drupal_db_backup.sql` ואת תיקיית `sites` ל-`sites_backup.tar.gz` |
| `restore.sh` | משחזר את בסיס הנתונים ואת תיקיית `sites` מקבצי הגיבוי ומפעיל מחדש את Drupal |
| `cleanup.sh` | מוחק את הקונטיינרים, ה-images, ה-volumes והרשת שהפרויקט יצר |
| `drupal_db_backup.sql` | גיבוי של בסיס הנתונים |
| `sites_backup.tar.gz` | גיבוי של תיקיית `sites` של Drupal |
| `chats/` | תיעוד השיחות עם כלי AI במהלך העבודה |

## מידע נוסף

- **הפעלת Docker:** לפני הרצת הסקריפטים חייבים לוודא ש-Docker רץ. ב-Windows עם WSL2, פותחים את Docker Desktop ומחכים ל-"Engine running".
- **גישה לאתר:** האתר זמין רק מהמחשב שמריץ את הקונטיינרים. גלישה לכתובת `localhost:8080` ממחשב אחר תציג את ה-Drupal של אותו מחשב, לא את האתר שלנו.
- **סוג התוכן "כתבה":** אצלנו, התקנה עם פרופיל Standard ב-Drupal 11.4 לא יצרה את סוג התוכן "כתבה". הוספנו אותו עם הכלי המובנה של Drupal (recipes), בפקודה:

<div dir="ltr">

```bash
docker exec -w /opt/drupal/web drupal-app ../vendor/bin/dr recipe core/recipes/article_tags
```

</div>

  התיקון שמור בבסיס הנתונים, ולכן לא צריך לחזור עליו אחרי שחזור.
- **אבטחה:** הקובץ `settings.php` שבגיבוי מכיל את סיסמת בסיס הנתונים. כאן זה מקובל, כי הסיסמה נקבעה בדרישות המטלה. בפרויקט אמיתי לא מעלים קובץ כזה למאגר ציבורי.
